# Globalresearch

글로벌리서치팀 업무개선용

## 시나리오 분석기

애널리스트가 제시한 시나리오에 해당하는 과거 사례를 찾아, 원하는 자산의 이후 수익률과 최대낙폭을 분석하는 프로젝트입니다.

## 현재 상태

기존 구현은 근원 CPI·비농업고용·ISM 제조업의 복합조건을 분석하는 프로토타입입니다. 현재 분석 기준은 [AGENTS.md](AGENTS.md)에 정리되어 있으며, 기존 코드에 모두 반영된 상태는 아닙니다. 이전 Claude 기반 작업의 이력은 Git 기록에서 확인할 수 있습니다.

문서는 핵심 운영 규칙, 상세 분석 방법, 검증 사례의 세 부분으로 관리합니다. 새 규칙은 담당 문서에서 수정하고 해당 검증 사례를 함께 갱신합니다. 문서에 정한 기준과 실제 구현·검증 상태를 구분합니다.

기존 코드의 출처·시간 처리·숫자 표기·보고서 형식에는 최신 명세와 차이가 있습니다. 구체적인 차이와 확인할 항목은 [검증 사례와 진행 상태](VALIDATION.md)에 기록합니다.

## 작업 시작 시 GitHub 지침 참조

이 프로젝트에서 새 작업을 시작하면 Codex는 로컬 [AGENTS.md](AGENTS.md)에 따라 [GitHub 저장소](https://github.com/jeongpal0405-wq/Globalresearch)의 `main` 최신 커밋을 확인하고, 그 버전의 AGENTS.md와 작업에 필요한 연결 문서를 읽습니다. 사용자가 매번 "GitHub 지침을 읽어"라고 요청할 필요는 없습니다. 구체적인 조회·적용·실패 처리 규칙은 AGENTS.md의 'GitHub 최신 지침 확인'에서 관리합니다.

- 사용 방법: 이 프로젝트에서 평소처럼 작업을 요청합니다. 시작 안내의 `GitHub 지침 확인: main@…`와 읽은 문서명으로 실제 조회 여부를 확인합니다.
- 필요한 조건: GitHub 플러그인이 연결되어 있고 이 저장소를 읽을 수 있어야 합니다. 연결에 실패하면 Codex가 알리고, 지침에 의존하는 분석을 보류합니다.
- 적용 범위: 새 작업과 명시적인 지침 갱신 요청에서 최신판을 확인합니다. 같은 작업의 후속 대화는 확인한 버전을 유지합니다. 다른 PC에서도 이 AGENTS.md와 GitHub 연결이 필요합니다.
- 구현 방식: Codex의 지침에 따른 조회 절차입니다. 별도 시작 훅이나 백그라운드 동기화 프로그램은 설치하지 않았습니다. 지침 참조와 로컬 파일 동기화·GitHub 업로드는 별개입니다.
- 검증 범위: 현재 대화에서 GitHub 최신 커밋과 지침 원문 조회를 확인했습니다. 새 작업에서 사용자 재지시 없이 이 절차가 실행되는지는 [검증 기록](VALIDATION.md)의 G02로 별도 확인합니다.

## 주요 파일

현재 작업 폴더 `AI 업무 개선/`가 실제 프로젝트 루트입니다. 이전의 같은 이름 하위 폴더는 2026-09-17에 통합했습니다. 아래 경로와 실행 명령은 모두 현재 루트를 기준으로 합니다.

```text
AI 업무 개선/
├─ AGENTS.md          핵심 운영 규칙
├─ README.md          프로젝트 설명
├─ ANALYSIS_METHOD.md 상세 분석 방법
├─ VALIDATION.md      검증 기록
├─ scripts/           수집·계산·보고서 생성
├─ tests/             계산 검증
├─ data/              수집 원본·분석 자료
├─ _out/              보고서·차트·계산 결과
├─ tmp/               로컬 임시 자료·폴더 통합 기록
├─ .git/              기존 Git 이력
├─ .gitignore         추적 제외 규칙
└─ .env               로컬 인증정보
```

| 파일 | 역할 |
|---|---|
| [AGENTS.md](AGENTS.md) | 모든 작업에 적용하는 핵심 운영 규칙과 문서 안내 |
| [ANALYSIS_METHOD.md](ANALYSIS_METHOD.md) | 조건·데이터·시간 결합·계산·결측·보고서의 상세 기준 |
| [VALIDATION.md](VALIDATION.md) | 검증 질문, 기대 동작, 실제 실행 결과, 미반영 항목 |
| [tests/test_eventstudy.py](tests/test_eventstudy.py) | 실제 데이터 없이 실행하는 기본 계산 검증 |
| `scripts/parse_investing.py`, `scripts/ingest_tsv.py` | 수집한 경제지표 원문 정제 |
| `scripts/load_events.py` | 이벤트 데이터 구조 검증 |
| `scripts/screen.py` | 기존 복합조건의 사례 선별 |
| `scripts/eventstudy.py`, `scripts/analyze.py` | 수익률·최대낙폭·통계 계산 |
| `scripts/check_anatomy.py` | 해석 문장과 수치 근거 대조 |
| `scripts/figures.py`, `scripts/report.py` | 기존 차트·보고서 생성 |
| `scripts/verify_stack.py` | HTML·PDF 생성 최소 구현 |
| `data/series_map.json` | 기존 지표 식별자 매핑; 새 출처 규칙에 맞춘 검토 필요 |

## Git에 포함하는 범위

코드, 운영·분석·검증 문서, 인공 자료를 사용하는 테스트, 이 설명서, 기존 지표 매핑을 버전 관리합니다.

`.gitignore`는 다음 파일을 Git 추적 대상에서 제외합니다. 로컬 파일은 삭제하지 않습니다.

- `.env` 등 인증정보 파일
- `data/series_map.json`을 제외한 `data/`의 수집 데이터와 분석 자료
- `_out/`의 생성 보고서·차트·계산 결과
- `tmp/`의 로컬 임시 자료·폴더 통합 기록
- Python 캐시·가상환경·백업 파일

따라서 저장소를 새로 내려받은 환경에는 분석 입력 데이터가 포함되지 않습니다. 분석하려면 지정 출처에서 필요한 데이터를 확보하고, 출처 및 발표 당시 값 검증을 거쳐 로컬에 준비해야 합니다. API 키를 코드나 커밋에 넣지 않습니다.

## 개발 환경

기존 작업 환경은 Windows와 Python입니다. 실행 전 실제 사용 가능한 Python과 라이브러리를 확인합니다. 아래는 이전 지침의 설치 기록이며 현재 환경을 보장하지 않습니다.

- Python 3.9.13 (Visual Studio 번들), 당시 실행 명령은 `py -3`.
- playwright 1.60 + Chromium 148, matplotlib 3.9.4, jinja2, fredapi, pyarrow, yfinance 1.2.0, pandas 2.2.2, PyMuPDF.
- 기존 기록의 호환성 대응 예시는 greenlet 3.1.1 고정. 환경을 확인하지 않고 그대로 재설치하거나 시스템 도구를 추가하지 않습니다.

설치 목록은 허용 출처 목록이 아닙니다. 의존성 잠금 파일과 새 환경에서의 전체 실행 검증은 아직 준비되지 않았습니다.

## 기본 계산 검증

numpy와 pandas가 있는 Python으로 프로젝트 루트에서 실행합니다. 아래 `python`은 실제 사용 가능한 실행기 경로로 바꿀 수 있습니다.

```text
python -m unittest discover -s tests -p "test_*.py" -v
```

테스트는 인공 가격으로 기존 계산 함수를 확인하며 외부 데이터 조회를 하지 않습니다. 통과해도 출처·발표 당시 값·대화 흐름·보고서까지 검증된 것은 아닙니다. 범위와 실행 상태는 VALIDATION.md에서 확인합니다.

Git 업로드 준비는 프로젝트 보관·변경 이력 관리를 위한 작업이며, 새 출처 정책 적용이나 범용 시나리오 분석 기능 구현을 의미하지 않습니다.
