기준: [AGENTS.md](../AGENTS.md), [상세 분석 방법](ANALYSIS_METHOD.md).

문서에 정의한 기대 동작, 기존 코드의 점검 결과, 실제 실행한 검증을 구분한다. 상태는 '미실행', '통과', '실패', '자료 확보 불가'로 기록하며 코드 열람만으로 실행 통과라고 쓰지 않는다.

## 1. 오프라인 계산 검증

[tests/test_eventstudy.py](../tests/test_eventstudy.py)는 기존 eventstudy.py의 계산 함수에 인공 가격을 입력한다. 실제 시장 자료를 사용하지 않고 가격 수집 모듈을 차단하므로 네트워크에 접근하지 않는다.

| ID | 확인 대상 | 입력과 기대 결과 | 실행 상태 |
|---|---|---|---|
| N01 | 발표일 종가 기준 | 전일 50.0, 발표일 100.0, 다음 거래일 101.0 → 1일 수익률 1.0% | 통과 |
| N02 | 거래일 계산 | 금요일 발표일 100.0, 다음 주 금요일 105.0 → 5거래일 수익률 5.0% | 통과 |
| N03 | 관찰기간 미완료 | 20거래일 가격은 없고 1거래일 가격은 있음 → 20일 결측, 1일 1.0% 유지 | 통과 |
| N04 | 최대낙폭 | 발표 전 고점 200.0을 제외하고 발표 후 100.0 → 110.0 → 88.0 → 99.0 → MDD -20.0% | 통과 |
| N05 | 통계 분모 | 수익률 3.0%, -1.0%, 결측, 0.0% → n=3, 평균 표시 0.7%, 중앙값 0.0%, 상승 비율 표시 33.3% | 통과 |
| N06 | 베이스라인 | 종가 100.0 → 110.0 → 121.0 → 유효 1일 구간 2개, 평균·중앙값 10.0%, 상승 비율 100.0% | 통과 |

N05의 표시값은 기대 문구다. 자동 검증은 원래 정밀도의 수치를 비교하며, 보고서 반올림 구현까지 검증하지 않는다.

실행 방법: 프로젝트 루트에서 사용 가능한 Python 실행기로 아래 명령을 실행한다. numpy와 pandas가 필요하며 yfinance는 이 검증에 필요하지 않다.

```text
python -m unittest discover -s tests -p "test_*.py" -v
```

실행 기록은 아래 '최근 점검 기록'에 남긴다. 이 검증 통과는 데이터 수집·출처 검증·조건 확인·보고서 생성의 전체 통과를 뜻하지 않는다.

## 2. 대화·데이터·전체 분석 검증 사례

아래는 앞으로 실행할 승인 기준이다. 실제 관측값은 지정 출처에서 검증하고, 인공 자료로 시험하는 경우 실제 시장 결과와 구분한다.

| ID | 상황 | 기대 동작 | 상태 |
|---|---|---|---|
| S01 | 지표 종류·조건·기간·자산·판정 시점·기산일·가격 기준까지 명확한 질문 | 조건 요약 후 진행. 이미 확정된 사항을 재질문하지 않음 | 미실행 |
| S02 | '물가가 높고 고용이 좋을 때 나스닥은?' | 지표·비교 기준·기간 등 모호한 부분을 질문. 답변 전 표본 선정·계산하지 않음 | 미실행 |
| S03 | 'VIX가 30을 넘었을 때' | 모든 초과일인지 최초 돌파일인지와 기산일을 확인. 임의 중복 제거·기준일 선택 금지 | 미실행 |
| S04 | 컨센서스가 필요한 조건과 실제치만 필요한 조건 | 전자는 Investing.com 브라우저 조회, 후자는 FRED API 우선 확인 후 필요 시 Investing.com. 출처·전환 이유 기록 | 미실행 |
| S05 | 현재 수정치만 있고 발표 당시 값을 확인할 수 없음 | '발표 당시 값 확보 불가'로 표시. 수정치로 조건을 판정하지 않음 | 미실행 |
| S06 | 컨센서스 결측 또는 기간 일부 누락 | 결측을 0·불충족으로 처리하지 않음. 확인된 사례 수와 미판정 수를 구분 | 미실행 |
| S07 | 완전한 인공 이력의 surprise가 각각 0.1%p, 0.0%p이고 조건은 0.2%p 이상 | 정확히 0건. 조건을 완화하거나 사례를 만들어 넣지 않음 | 미실행 |
| S08 | 기산일 종가 이후에야 확정되는 조건 포함 | 시점 차이를 설명하고 사후 비교 여부를 사용자에게 확인. 기산일에 알려진 조건처럼 보고하지 않음 | 미실행 |
| S09 | 휴장·시차·장 마감 후 발표 | 거래일 연결을 사용자에게 확인. 자동으로 다음 거래일에 옮기지 않음 | 미실행 |
| S10 | 실제 거래일의 중간 가격이 누락 | 휴장으로 처리해 h일을 당기지 않음. 영향받는 성과를 결측 처리 | 미실행 |
| S11 | 반복·OR·순서 조건 | 확정한 집계 방식 적용, OR 중복 제거와 순서 시간 간격 확인. 미지원이면 구현·검증 필요를 명시 | 미실행 |
| S12 | 수치·자체 해석·PDF 산출 | 한 자리 반올림, 해석별 관측 근거, 사용 출처, 전체 사례와 한계 표시. 모든 면의 잘림·겹침 확인 | 미실행 |

## 3. 기존 구현에서 확인된 차이

2026-09-16 코드 열람 기준이며 아래 항목은 수정 완료 기록이 아니다.

| 항목 | 현재 구현 | 다음 검증 대상 |
|---|---|---|
| 출처 | prices.py는 yfinance, fetch_bls.py는 BLS 직접 조회 사용 | AGENTS.md의 지정 출처와 당시 값 확인 적용 후 S04·S05 |
| 범용 조건 | screen.py는 세 지표·임계값·참조월 결합 고정 | 사용자 확인 조건을 반영하는 흐름과 S01~S03·S11 |
| 시간 | eventstudy.anchor는 휴장 시 다음 가격 날짜로 자동 이동, screen.py는 날짜 단위 비교 | 시각·시장 달력·사용자 확인을 적용한 S08~S10 |
| 결측 | 계산 함수 일부는 NaN을 반환하지만 사유 분류·보고가 전체 흐름에서 검증되지 않음 | S06·S07·S10, 자산·기간별 유효 n 표시 |
| 정밀도 | analyze.py는 중간 결과를 소수 둘째 자리로 반올림, report.py는 두 자리 표시 | 원정밀도 유지와 한 자리 표시를 분리한 S12 |
| 당일 성과 | analyze.py의 0일 값에 전일 종가 대비 발표일 등락을 저장 | 기본 산출물의 1·5·20·60거래일 구성 일치 여부 |
| 보고서 | report.py는 기존 PPTX 생성, verify_stack.py는 PDF 최소 구현 | 현재 PDF 명세에 맞춘 생성·텍스트·렌더 검증 |

기존 이벤트 파일은 세 지표별 99행이며, 저장된 결과에는 복합조건 충족 사례 2건이 있다. 이는 기존 실행 산출물의 현황이며 새 출처·발표 당시 값 규칙을 충족했다는 검증 근거는 아니다. 새 분석에 재사용하기 전에 확인한다.
