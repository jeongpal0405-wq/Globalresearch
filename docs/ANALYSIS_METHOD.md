# 상세 분석 방법

핵심 출처·확인·보안 원칙은 [AGENTS.md](../AGENTS.md)를 따른다. 이 문서는 조건을 데이터와 계산으로 옮기는 기준을 관리한다. 구현 여부와 실행 증거는 [검증 사례](VALIDATION.md)에 별도로 기록한다.

## 1. 질문을 분석 조건으로 기록

분석 전에 아래 항목을 정리한다. 사용자가 이미 확정한 내용은 그대로 적용하고, 결과를 바꾸는 미확정 항목만 질문한다.

| 항목 | 기록할 내용 |
|---|---|
| 대상 | 지표의 국가·종류·전월비/전년비·헤드라인/근원, 자산명과 정확한 식별자 |
| 조건 | 실제치·예상 대비 차이·변화율 중 판정값, 비교 연산자, 임계값과 단위 |
| 결합 | 모두 충족(AND), 하나 이상 충족(OR), 발생 순서, 허용 시간 간격 |
| 시간 | 분석 대상 기간, 각 조건의 판정 시점, 기산일, 시간대·시장 |
| 반복 | 모든 충족일인지 최초 돌파일인지, 연속 발생을 한 사례로 묶을지 |
| 성과 | 관찰 거래일 수, 종가의 조정·배당·통화 기준 |
| 확인 기록 | 사용자의 원 질문, 확인 질문·답변, 최종 조건 요약 |

- 기본 관찰 구간은 1·5·20·60거래일이다. 사용자가 다른 구간을 명시하면 기록해 적용한다.
- 예를 들어 'CPI 상회'에서 지표 종류·서프라이즈 폭이 불명확하거나, 'VIX 30 초과'에서 반복 처리 방식이 불명확하면 사용자에게 확인한다.
- 주가 하락·VIX 돌파처럼 발표일이 없는 조건은 기산일을 사용자에게 확인한다. 경제지표의 발표일을 임의로 만들어 넣지 않는다.
- 순서·OR 조건 등을 문서에 표현할 수 있다는 사실은 기존 코드가 지원한다는 뜻이 아니다. 필요한 구현과 검증을 확인한 뒤 사용한다.

## 2. 데이터 확보와 당시 값 검증

### 출처와 수집 범위

- 출처 선택 순서는 AGENTS.md의 '출처와 데이터'를 따른다. 계열 이름이 비슷하다는 이유로 자산·지표·주기·단위를 바꾸지 않는다.
- 경제지표는 전체 발표 이력, 시장 조건은 전체 대상 거래일에서 표본을 만든다. 상회·부합·하회나 조건 불충족일을 수집 단계에서 제외하지 않는다.
- 요청 기간, 실제 확보 기간, 예상되는 관측 주기, 중복·누락·미판정 건수를 확인한다. 화면에 표시된 일부 행을 전체로 간주하지 않는다.
- 기존 수집량이나 시작일을 새 분석의 고정 상한으로 삼지 않는다. 확보 범위가 요청 범위보다 짧으면 그 차이를 보고한다.
- 브라우저 조회 기록 또는 API 식별자와 원본 파일을 연결해 보존한다. 정제·재수집·정정 시 기존 원본을 덮어쓰지 않는다.
- 원본과 검증된 정제본은 로컬에 보존한다. 출처·수집 범위·당시 값 검증이 없는 기존 캐시는 그대로 재사용하지 않는다.

### 최소 기록 항목

| 구분 | 항목 |
|---|---|
| 발표 | release_date, release_time, timezone, indicator, variant |
| 값 | actual, forecast, previous, unit, ref_period |
| 출처 | source_ref, pulled_on, raw_file, 실제 수집 범위 |
| 당시 값 | value_as_of, 당시 값 확인 근거, 확인 성공/실패 |
| 품질 | 결측·중복·개정·정정 기록, notes |
| 가격 | 자산 식별자·시장·거래일·통화·종가·조정 여부·출처 |

- 월간 자료는 ref_period를 기존 ref_month와 연결한다. 주간·분기 자료에는 해당 기준기간을 보존한다. 주기와 참조기간을 임의로 추정하지 않는다.
- 표에 월만 표시된 월간 자료는 발표일과 함께 연도를 확인한다. 1월 발표의 12월 자료는 전년이다. 불명확한 경우 원자료를 다시 확인한다.
- 경제지표 actual은 해당 발표 회차의 실제치, forecast는 발표 전 당시 예상치, previous는 해당 발표 시점에 제시된 전기 값이다. 이후 수정치를 섞지 않는다.
- 최신 API 응답이나 현재 히스토리 표라는 이유만으로 발표 당시 값이라고 간주하지 않는다. 당시 값이라는 근거가 없으면 '발표 당시 값 확보 불가'로 기록한다.
- 발표 시각을 확인하지 못하면 임의 시각을 넣지 않는다. 그 시각에 의존하는 조건은 판정을 보류한다.
- forecast 공란은 NaN으로 남긴다. 컨센서스가 필요한 조건은 판정 불가이며, 실제치만 필요한 별도 조건과 구분한다.

## 3. 조건 판정과 시간 결합

- surprise = actual - forecast. 원본 정밀도를 유지해 계산한다. 퍼센트 지표의 차이는 %p, 천 명 단위 고용지표는 K, ISM은 지수 포인트로 비교한다. bp와 %p를 혼용하지 않는다.
- 화면 표시용 반올림을 조건 판정에 사용하지 않는다. 임계값 경계에서는 원본 소수 정밀도를 유지하는 계산 방식으로 부동소수점 오차를 처리한다.
- 월간 지표를 같은 참조월로 묶을지, 기산 시점까지 공개된 최신 발표를 사용할지 등은 사용자 확인 내용대로 적용한다. 단순히 날짜·참조월이 같다는 이유로 연결하지 않는다.
- 각 값의 공개 시점을 확인해 당시 알 수 없던 정보가 조건에 섞이지 않도록 한다. 기산일 이후 확인된 조건을 이용한 사후 비교는 사용자 확인과 보고서 표시가 필요하다.
- AND 조건은 전체 → 조건 1 → 조건 2 순으로 단계별 사례 수를 센다. OR 조건은 조건별 사례 수와 중복 제거 후 합집합 수를 보여준다. 순서 조건은 사용자 확인된 순서·시간 간격을 적용한다.
- 반복 충족일의 집계 단위는 사용자 확인 내용에 따른다. 결과를 본 뒤 임의로 날짜를 빼거나 합치지 않는다.
- 레짐 분류는 당시 관측 가능한 정보로 수행한다. 사후에 지정된 경기전환일을 당시 알려진 정보로 사용하지 않는다.

## 4. 수익률과 통계

### 종가·거래일 기준

- 확정된 기산일의 종가를 t=0으로 둔다. 경제지표의 기본 기산일은 발표일이며 다음 거래일이 1일이다.
- 수익률(%) = (t+h 거래일 종가 / t 종가 - 1) × 100.
- 발표일 종가 이전의 등락은 포워드 수익률에 포함하지 않는다. 차트의 t=0 수익률은 0.0%다.
- 대상 자산의 실제 거래일 달력으로 h를 센다. 휴장은 건너뛰되, 거래일의 가격 결측을 휴장으로 간주해 관찰기간을 당기지 않는다.
- 기산일 가격이 없거나 휴장·장 마감 후 발표·해외 시차로 기준이 모호하면 사용자에게 확인한다. 자동으로 다음 거래일에 연결하지 않는다.
- 종가의 주식분할 조정·배당 포함 여부·통화 기준을 명시하고 기간 전체에 동일하게 적용한다. 미확정인 경우 사용자에게 확인한다.
- 필요한 가격이 없으면 해당 성과는 결측으로 남긴다. 이후 60거래일이 지나지 않았다고 계산 가능한 1·5일 성과까지 지우지 않는다.

### 최대낙폭과 베이스라인

- h거래일 최대낙폭(%) = min(P_s / max(P_u, t ≤ u ≤ s) - 1) × 100, t ≤ s ≤ t+h. 기산일을 포함한 종가 경로로 계산하며 낙폭은 0 이하로 표시한다.
- 무조건부 베이스라인은 같은 자산·분석 범위·가격 기준·관찰 구간으로 계산한다. 구간 내 시작점 중 필요한 가격 경로가 확보된 날짜만 해당 통계에 포함하고 실제 범위를 기록한다.
- 사례의 평균은 베이스라인 평균, 중앙값은 중앙값, 상승 비율은 상승 비율과 비교한다. 예시 수치를 실제 베이스라인으로 재사용하지 않는다.
- 상승 비율은 유효 수익률 중 0보다 큰 수익률의 비율이다. 수익률 0은 상승에 포함하지 않으며 결측은 분모에서 제외한다.
- 조건 충족 사례 수와 자산·기간별 유효 사례 수를 구분한다. 결측을 제외한 이유와 건수를 남긴다.
- n < 10이면 '표본이 적어 결과의 불확실성이 큼, 사례 참고용'으로 표시한다. 표본 수만으로 통계적 유의성 유무를 단정하지 않는다.
- 1·5·20·60거래일 등 실제 사용한 구간별로 관찰기간 중첩을 확인한다. 중첩 표본을 모두 독립 사례로 해석하거나 명목 n을 곧바로 유효 n이라고 부르지 않는다.
- 시장 환경이 다른 사례는 당시 관측된 레짐으로 구분한다. 사후적으로 유리한 분류·임계값만 골라 결과를 강조하지 않는다.

### 표시 정밀도

- 저장·조건 판정·통계 계산은 원래 정밀도를 유지한다. 보고서·표·차트·코멘트에 표시할 때만 소수점 첫째 자리까지 반올림한다.
- 예: 3.43 → 3.4, 5.75 → 5.8, +0.34%p → +0.3%p. 날짜·사례 수·식별자에 불필요한 .0을 붙이지 않는다.
- 표시용으로 반올림한 수익률을 다음 계산의 입력으로 재사용하지 않는다. 단위와 부호를 명시한다.

## 5. 결과 상태와 자체 해석

| 상태 | 처리 |
|---|---|
| 조건 충족 사례 없음 | 필요한 범위를 모두 확인해 0건인 경우. 조건을 완화하지 않고 범위와 단계별 사례 수를 보고 |
| 판정 자료 부족 | 값·컨센서스·발표 시각·당시 값 근거 등이 없어 판정 불가. 불충족으로 집계하지 않음 |
| 관찰기간 미완료 | 조건은 충족했으나 이후 h거래일이 지나지 않음. 해당 구간만 미완료 표시 |
| 가격 자료 부족 | 필요한 거래일 가격이 없음. 관찰기간 미완료와 구별하고 대체 가격을 넣지 않음 |
| 수집 실패 | 접속·조회 실패로 아직 확인하지 못함. 데이터 자체가 없다고 단정하지 않음 |

- 일부 행을 판정하지 못했다면 확인된 사례 수와 미판정 수를 함께 적는다. 불완전한 범위를 '전체에서 0건'이라고 보고하지 않는다.
- 모든 조건에 대해 확인된 수치와 자체 해석을 설명한다. 해석의 근거인 관측값을 같은 단락에 제시한다.
- 관찰과 해석을 분리하고 해석은 '~로 해석'·'~로 판단'으로 표시한다. 동시 움직임만으로 인과관계를 확정하지 않는다.
- 근거가 부족하면 해당 항목에 '관측 데이터만으로 원인 특정 불가'라고 적는다. 기사나 전문가 의견으로 빈칸을 채우지 않는다.
- 발표일 종가 이후 성과를 발표 직후의 즉각적인 반응이라고 표현하지 않는다.

## 6. 보고서 구성과 확인

### 구성

- A4 세로 PDF, 증권사 리서치 보고서 형식으로 작성한다. 기존 참고 형식은 한화투자증권 주간 파생시황이다.
- 첫 면: 작성일·질의·실제 분석 범위, 조건 정의 표, 조건 충족일별 자산 성과 표를 싣는다.
- 조건 정의 표: 조건 번호·지표·variant·임계값·기산일/판정 역할. 아래에는 사용자 확인된 시간 결합 기준, 발표일 종가·거래일 기준, 컨센서스 출처를 적는다.
- 성과 표: 기산일·각 조건 값·대상·1일·5일·20일·60일·60일 MDD 순. 날짜와 조건 값은 자산별 행에서 묶고, 내부 참조기간은 필요하지 않으면 열을 차지하지 않는다.
- 단계별 사례 수, 기간별 유효 n, 베이스라인, 표본·결측 한계는 관련 표 주변에 표시한다. 별도 고지 면으로 밀어내거나 생략하지 않는다.
- n ≤ 20이면 개별 사례를 발생 순서대로 전부 설명한다. 기본 구성은 요약 1면 + 사례당 1면이지만, 가독성 때문에 필요한 추가 면은 허용한다.
- 각 사례: 조건에 사용한 모든 지표의 배경, 발표일 종가 이후 첫 1거래일 반응, 이후 경로와 최대낙폭, 차트 2개를 싣는다. 확보된 세부지표 범위에서만 설명한다.
- 차트: -20~+60거래일 가격 경로를 발표일 종가 기준으로 표시하고 사전 구간과 이후 구간을 구분한다. 구간 수익률 막대는 1·5·20·60거래일이다.
- n > 20이면 요약·분포와 전체 사례 목록을 어떻게 배치할지 사용자와 협의한다. 임의로 일부 사례만 고르지 않는다.
- 사례가 0건이면 조건·확보 범위·단계별 결과·한계를 보고하고 존재하지 않는 사례 표·차트를 만들지 않는다.

### 문체와 구현

- 본문은 개조식·음슴체로 쓰고 단락당 4~6줄을 기준으로 한다. 관측 사실과 계산·해석을 구별하며 전망·투자의견 표현은 넣지 않는다.
- 표는 면당 최대 2개, 본문은 8pt 이상으로 유지한다. 분량이 넘치면 면을 늘리고 사례 번호를 이어 표시한다.
- 각 그림 아래에는 실제 사용한 출처와 자체 계산 여부만 적는다. 원본 주소·조회 기록은 분석 기록에서 추적 가능하게 보존한다.
- 구현은 Jinja2 HTML + CSS paged media + Playwright Chromium의 page.pdf()를 사용한다. 기존 PDF 최소 구현은 [verify_stack.py](../scripts/verify_stack.py)를 참고한다.
- HTML과 body의 기본 여백을 제거하고, 면 나눔·2열 차트·표 break-inside: avoid·페이지 번호를 확인한다. Windows 네이티브 의존성이 필요한 WeasyPrint로 임의 전환하지 않는다.
- 차트는 matplotlib PNG, 150dpi 이상. 한글 폰트는 Malgun Gothic, axes.unicode_minus = False를 설정하고 실제 표시를 확인한다.
- PyMuPDF로 한글·수치·부호·페이지 수를 확인하고 모든 페이지를 이미지로 렌더해 잘림·겹침을 검수한다. 페이지 수는 추가 면을 포함해 계획한 구성과 대조한다.
- 결과·HTML·차트·검증 이미지는 로컬 _out/에 저장한다. 보고서 생성 코드를 실행했다는 이유만으로 데이터·계산 검증이 끝났다고 보고하지 않는다.
